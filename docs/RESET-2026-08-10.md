## סיכונים שנשארים פתוחים בזמן הביצוע

**סיכון הטריגרים — נסגר בנתונים.** ראה הטבלה בסעיף הבא. אחד בלבד יורה על DELETE, והוא זה שמושעה.

**שני הטריגרים שאין להם מיגרציה בריפו** — `trg_auditor_invoice_document_company_check` ו-`trigger_enforce_document_number_integrity` — עדיין חסרים, וזה נשאר רשום ב-`FOLLOWUPS.md` תחת סחף מסד-קוד. **זה כבר אינו סיכון לאיפוס** אלא פער תשתית שממתין לטיפול נפרד.

**המסד משותף בין כל הסביבות.** אין סביבת בדיקה לשחזר אליה ולאמת — שחזור, אם יידרש, הוא לייצור.

**השעיית `trigger_prevent_final_delete`** תופסת `SHARE ROW EXCLUSIVE` וחוסמת כתיבות מקבילות, ו-DDL ב-PostgreSQL טרנזקציוני — ולכן ההשעיה אינה נראית לסשן אחר לפני ה-`COMMIT` ומתגלגלת אחורה ב-`ROLLBACK`. **פונקציית ההגנה עצמה לא שונתה.**

## ששת הטריגרים על `public.documents` — הראיה שהשעיה אחת מספיקה

הוצא מ-`pg_trigger` מול הייצור. **רק אחד יורה על DELETE.**

| טריגר | אירוע | יורה על DELETE | הגדרה בריפו |
|---|---|:-:|---|
| `before_invoice_receipt_insert` | `BEFORE INSERT` | לא | `scripts/043-fix-conversion-logic.sql:146` |
| `trg_auditor_invoice_document_company_check` | `BEFORE UPDATE OF company_id` | לא | **חסרה** |
| `trigger_enforce_document_immutability` | `BEFORE UPDATE` | לא | `scripts/044-allow-final-close.sql:78` |
| `trigger_enforce_document_number_integrity` | `BEFORE INSERT OR UPDATE` | לא | **חסרה** |
| `trigger_log_document_event` | `AFTER INSERT OR UPDATE` | לא | `scripts/006-tenant-isolation-and-audit.sql:430` |
| **`trigger_prevent_final_delete`** | **`BEFORE DELETE`** | **✅ היחיד** | `scripts/006-tenant-isolation-and-audit.sql:352` |

ההגדרות המלאות, מ-`pg_get_triggerdef` על הייצור:

```sql
CREATE TRIGGER before_invoice_receipt_insert BEFORE INSERT ON public.documents
  FOR EACH ROW EXECUTE FUNCTION set_invoice_receipt_paid()

CREATE TRIGGER trg_auditor_invoice_document_company_check BEFORE UPDATE OF company_id
  ON public.documents FOR EACH ROW EXECUTE FUNCTION auditor_charge_invoice_company_id_check()

CREATE TRIGGER trigger_enforce_document_immutability BEFORE UPDATE ON public.documents
  FOR EACH ROW EXECUTE FUNCTION enforce_document_immutability()

CREATE TRIGGER trigger_enforce_document_number_integrity BEFORE INSERT OR UPDATE
  ON public.documents FOR EACH ROW EXECUTE FUNCTION enforce_document_number_integrity()

CREATE TRIGGER trigger_log_document_event AFTER INSERT OR UPDATE ON public.documents
  FOR EACH ROW EXECUTE FUNCTION log_document_event()

CREATE TRIGGER trigger_prevent_final_delete BEFORE DELETE ON public.documents
  FOR EACH ROW EXECUTE FUNCTION prevent_final_document_delete()
```

**המסקנה:** `trigger_prevent_final_delete` הוא היחיד שיורה על DELETE, ולכן השעייתו לשני משפטים היא כל מה שנדרש. חמשת האחרים אינם יורים בטרנזקציה הזאת בכלל — היא אינה עושה `insert` ואינה עושה `update` על `public.documents`.

**ופרט שההגדרות חושפות ולא היה ידוע קודם:** הפונקציה שמאחורי `trg_auditor_invoice_document_company_check` נקראת **`auditor_charge_invoice_company_id_check()`** — שם שאינו נגזר משם הטריגר, ולכן הניחוש הקודם שלי (`auditor_invoice_document_company_check`) היה שגוי. גם היא וגם `enforce_document_number_integrity()` **אינן קיימות בריפו**, וזה נשאר רשום ב-`FOLLOWUPS.md` תחת סחף מסד-קוד. שמן המדויק כאן הוא מה שיאפשר לחלץ אותן.
